It is the sanctioned one-double-cast-at-construction idiom, commented with the seam-check evidence (TS2351 default vs named), and the factory is the only place that knows the real SDK shape. Correct under the repo's own rules.
- **cancel-in-progress: true can produce a duplicate digest.** A run cancelled after sendDigest but before persistJudged leaves those posts unseen; the next tick re-judges and re-sends. This is F021's accepted one-duplicate-digest cost with a new trigger, and the alternative (queueing behind a parked SDK workflow) backs the schedule up unboundedly — the flip is right. Atomic state writes make every cancel point safe; the worst case is one repeat email.
- **resolveSurfaces THROWS on a linkedin surface** (config-file.ts:226-232). Reads as a landmine in a resolver; it is a deliberate wiring-bug tripwire for the partition invariant, with the error naming the fix. Fail-visible doctrine applied correctly.

- **fetchLinkedInPosts is console.warn-everything.** Six distinct warn sites and no throw: that IS the module's documented totality contract (D5/D10), each warn naming surface + typed cause. The belt catch in index.ts:235-242 is labeled as belt, not primary.
- **Carried, re-verified standing:** user!/pass! in email.ts (guarded above), Math.random in stateTempPath (unique-sibling legitimacy), heartbeat errors swallowed as warns (sanctioned best-effort), gate-destructive fail-open + regex evadability (seatbelt, not sandbox), logged-out fallback on an invalid Threads session (sanctioned degradable), probe's weak 2xx-success check (transport-health classifier, documented), the 429 rewind bound (judge.ts — each 429 iteration cools a distinct account).
