# Platform Toggle Implementation Plan

## Overview

Add the required `platforms: { linkedin, threads }` boolean block to `watcher.config.json` and gate each acquisition arm with its flag. The approach is the partition filter (Option 1 of the solutions artifact): intersect the two existing surface arms at `src/index.ts:189-194`, so the existing empty-guards are the entire gating machinery, and return the Gate-1 shape after the secret resolve when both flags are false.

## Requirements

- Required `platforms` block with two boolean members; absent or malformed fails the run naming the file and key.
- Each flag gates its own platform only: no fetch, no judge, and none of its posts or leg lines in the digest or heartbeat (the subject template itself is unchanged render, D10).
- Both off: exit 0, no email, no state read, no state write. The secret check still runs (locked discover decision).
- The PC LinkedIn leg keeps fetching and validating (locked decision, a hosted-run-only toggle).
- `npm run typecheck && npm run lint && npm test` green at the end.

## Current State Analysis

The closed `ALLOWED_KEYS` tuple (`src/config-file.ts:44-51`) lists six keys; every valid file fails the unknown-key check until `platforms` joins it. `validateConfig` (`:84-106`) runs one validator per key and joins the results into the returned object. `readStringArray` (`:108-128`) is the required-reject validator template. `readScrollRounds` (`:208-218`) never floors a wrong value. `runWatcher` partitions raw surfaces at `src/index.ts:189-194` into `linkedinSurfaces` (payload reader) and `surfaces` (resolved threads records); both fetch arms are empty-guarded (`:209`, `:216`, `:220`). The health resolve hoists above Gate 1 (`:264-283`, the recorded accepted trade: malformed `LLM_ACCOUNTS` exit-1s even a nothing-unseen tick). Gate 1 returns `{ judged: 0, matches: 0, skipped: 0, saved: false }` at `:310`.

### Key Discoveries

- Both fetch arms already skip on `.length === 0` (`src/index.ts:209/:216/:220`). The flag intersection is the whole funnel wiring; no new skip machinery.
- `resolveSurfaces` throws if a linkedin surface reaches it (`src/config-file.ts:229-233`). The threads-arm filter must keep the `type !== "linkedin"` exclusion.
- `scripts/fetch-linkedin.ts:237`, `scripts/probe-judge.ts:50`, and `scripts/probe-linkedin.ts:26` load the FULL config. A required key breaks stale clones, fail-visible by design; same-commit discipline applies.
- Three `WatcherConfig` literals exist: `CONFIG` and `MIXED_CONFIG` (`tests/index.test.ts:41/:51`, the latter spreads the former) and `CONFIG` (`tests/fetch-linkedin.test.ts:37`). All three gain the required member in Phase 1 (verified by an exhaustive repo scan).
- `buildSubject` appends `" + LinkedIn"` only when at least one match is non-threads (`src/email.ts`, D10). Rendering needs zero changes.
- Biome: lineWidth 100, double quotes, 2-space indent. All plan code is written to survive `biome check`.

Caller shape: `{ judged: 0, matches: 0, skipped: 0, saved: false }` (the Gate-1 shape).

## What We Are NOT Doing

- No env-var kill switch. `HEARTBEAT_ENABLED` stays separate by decision.
- No PC-leg honoring of the flags. The loop keeps fetching and validating (locked decision).
- No render changes in `email.ts` or `heartbeat.ts`. A disabled platform never produces a non-threads match and never attaches `linkedinLeg`, so the existing conditionals already omit it.
- No workflow changes: file-based config, no new secret.
- No funnel reorder. `resolveJudgeConfig` stays hoisted (recorded trade `src/index.ts:264-270` untouched). Option 2 was rejected in the solutions artifact.

## Decisions

### Required block validated by readPlatforms (three reject levels)

Explored: optional-with-default (the `readScrollRounds` shape) versus required-reject. Decision: required, three levels (absent block / missing member / non-boolean member); every error names path + key; never floors. Modeled after `readStringArray` (`src/config-file.ts:108-128`). Rationale: which platforms run is an operator decision; a silent default would fetch a leg the operator turned off. Extra members inside the block are ignored (the `readSurfaces` entry precedent). The exported `PlatformFlags` interface mirrors the committed file member order.

### Partition filter with zero ordering change (Option 1)

The flag intersection lands at the existing raw partition (`src/index.ts:189-194`); both arms and their empty-guards do the gating. Normal-tick ordering, including the recorded hoist trade, stays byte-identical. Option 2 (early gate) was rejected in the solutions artifact: it flips the recorded trade for every tick. Option 3 (a gate-helper module) was rejected as packaging tax; its truth-table cases become validator tests.

### Both-off parked return after the health resolve

Placement: between the degraded-accounts warn block and the `HeartbeatStats` construction. The secret resolve (`resolveJudgeConfig`) has already run, so a malformed `LLM_ACCOUNTS` exits 1 while parked (locked discover decision). Nothing below the return runs: no `loadState`, no heartbeat email, no flush, no persist. The return shape is the Gate-1 shape (`src/index.ts:310`).

### D14 raw-config truth kept on the surfaces lines (delegated call)

The developer delegated this ("find the best UX"). Decision: the startup surfaces line and the extract count keep mirroring the raw config even when a platform is off. Rationale: one invariant holds in every mode — the surfaces line always equals the surfaces array of watcher.config.json — and the new `watch: platforms:` line carries enabled-truth upfront. The D14 comment is amended to state the invariant instead of the outdated "surfaces the run attempts".

### Code and watcher.config.json ship in one commit

The key is required, so the config block and the validator land together: old code + new config fails the unknown-key check; new code + old config fails the required-key check. Both directions fail visibly. This is correctness, not hygiene.

```typescript
  keywords: string[];
  candidateTerms: string[];
  surfaces: Surface[];
  platforms: PlatformFlags;
  recencyHours: number;
  reasoningEffort: ReasoningEffort;
  scrollRounds: number;
}

// 1c. ALLOWED_KEYS — full replacement (platforms joins after surfaces).
const ALLOWED_KEYS = [
  "keywords",
  "candidateTerms",
  "surfaces",
  "platforms",
  "recencyHours",
  "reasoningEffort",
  "scrollRounds",
] as const;

// 1d. validateConfig — full replacement (validator wiring + return object).
function validateConfig(parsed: unknown, filePath: string): WatcherConfig {
  if (parsed === null || typeof parsed !== "object" || Array.isArray(parsed)) {
    throw new Error(`config: ${filePath} must contain a JSON object`);
  }
  const record = parsed as Record<string, unknown>;

  for (const key of Object.keys(record)) {
    if (!(ALLOWED_KEYS as readonly string[]).includes(key)) {
      throw new Error(
        `config: ${filePath} has unknown key "${key}" — allowed keys: ${ALLOWED_KEYS.join(", ")}`,
      );
    }
  }

  const keywords = readStringArray(record.keywords, "keywords", filePath, true);
  const candidateTerms = readStringArray(record.candidateTerms, "candidateTerms", filePath, false);
  const surfaces = readSurfaces(record.surfaces, filePath);
  const platforms = readPlatforms(record.platforms, filePath);
  const recencyHours = readRecencyHours(record.recencyHours, filePath);
  const reasoningEffort = readReasoningEffort(record.reasoningEffort, filePath);
  const scrollRounds = readScrollRounds(record.scrollRounds, filePath);

  return {
    keywords,
    candidateTerms,
    surfaces,
    platforms,
    recencyHours,
    reasoningEffort,
    scrollRounds,
  };
}

// 1e. New validator, placed after readSurfaces.
/**
 * Required per-platform switches: an absent block, a missing member, or a
 * non-boolean member each fail with the path and the key. Which platforms
 * run is an operator decision, so there is no default to fall back to.
 * Extra members inside the block are ignored (the readSurfaces precedent).
 */
function readPlatforms(value: unknown, filePath: string): PlatformFlags {
  if (value === null || typeof value !== "object" || Array.isArray(value)) {
    throw new Error(
      `config: ${filePath} "platforms" must be an object with "linkedin" and "threads" boolean members`,
    );
  }
  const record = value as Record<string, unknown>;
  const linkedin = record.linkedin;
  if (linkedin === undefined) {
    throw new Error(
      `config: ${filePath} "platforms.linkedin" is required — true watches the platform, false skips it`,
    );
  }
  if (typeof linkedin !== "boolean") {
    throw new Error(
      `config: ${filePath} "platforms.linkedin" must be a boolean, got ${JSON.stringify(linkedin)}`,
    );
  }
  const threads = record.threads;
  if (threads === undefined) {
    throw new Error(
      `config: ${filePath} "platforms.threads" is required — true watches the platform, false skips it`,
    );
  }
  if (typeof threads !== "boolean") {
    throw new Error(
      `config: ${filePath} "platforms.threads" must be a boolean, got ${JSON.stringify(threads)}`,
    );
  }
  return { linkedin, threads };
}
```
